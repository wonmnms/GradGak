# Requirements

> 이 문서는 (현재 Phase 기준) **상세 기능/데이터 요구사항**을 다룬다. 배경·목표·Phase 로드맵·개발 원칙 등 전략 수준은 [project-plan.md](./project-plan.md) 참고.

## 1. 기능 요구사항

### 1.1 사용자 정보 입력

사용자는 다음 정보를 입력할 수 있어야 한다. 입학년도·학과는 MVP 지원 범위가 하나뿐이라([project-plan.md](./project-plan.md) 6번) 고정값으로 처리한다.

- 프로그램: 공학 / 일반
- 세부전공: 소프트웨어전공 / 인공지능전공
- 졸업논문(작품) '가' 판정 여부
- TOPCIT 응시 여부

졸업논문·TOPCIT는 이수내역 PDF에 나오지 않는 정보라 사용자가 직접 입력한다. 복수전공·부전공은 Phase 4 범위다.

### 1.2 이수과목 입력

이수과목은 KLAS 이수내역 PDF를 업로드하는 방식으로 입력한다.

1. 사용자가 KLAS 이수내역 PDF를 업로드한다
2. 시스템이 PDF에서 이수과목(수강 학기, 과목명, 이수구분, 학점, 성적, 재수강 여부)을 자동으로 추출한다
3. 추출 결과가 틀릴 수 있으므로 사용자가 확인하고 과목을 추가·삭제·수정한다
4. 검수를 마친 이수과목으로 졸업요건을 분석한다

- 로그인 없이 사용하며, 서버는 업로드한 PDF와 이수과목을 저장하지 않는다(요청 단위로 처리 후 폐기)
- 텍스트를 읽을 수 없는 PDF나 이수내역이 아닌 파일은 이유와 함께 안내한다
- 요청/응답 형식은 [api-spec.md](./api-spec.md) 참고

### 1.3 졸업요건 분석

시스템은 사용자 입력과 이수과목을 바탕으로 소프트웨어학부 졸업요건 4가지를 분석해야 한다.

| 요건 | 판정 방식 | 공학/일반 구분 |
| --- | --- | --- |
| 프로그램별 졸업이수학점 | 영역별(교양·전공 등) 최소 학점 합산 | 프로그램별로 다름 |
| 세부전공필수교과목 | 지정 과목 중 일정 개수 이상 이수 (인공지능전공만 해당, 소프트웨어전공은 없음) | 공학·일반 공통 |
| 졸업논문(작품) '가' 판정 | 사용자 입력 | 공학·일반 공통 |
| TOPCIT 응시 | 사용자 입력 | 공학·일반 공통 |

4가지를 모두 충족해야 졸업요건을 충족한다.

프로그램별 학점 요건은 다음과 같이 판정한다.

- 공학프로그램 선택 시: 공학 요건과 일반 요건을 **모두** 판정하며, 둘 다 충족해야 졸업요건을 충족한다
- 일반프로그램 선택 시: 일반 요건만 판정한다 (입학 시 기본값은 공학프로그램이며, 일반프로그램 전환은 특정 조건을 만족한 경우에만 가능)
- 같은 과목도 프로그램에 따라 전공 학점 인정 여부가 다를 수 있다 (예: C프로그래밍 계열은 일반프로그램에서 전공 학점 미포함)

학점 요건 각 영역에 대해 다음 정보를 제공해야 한다.

- 요구 조건
- 현재 이수량
- 부족한 양
- 충족 여부

### 1.4 부족 요건 안내

졸업요건을 충족하지 못한 경우 부족한 요건을 사용자에게 명확하게 표시해야 한다.

예시:

```text
전공필수
27학점 필요 / 21학점 이수
→ 6학점 부족
```

필수 과목을 이수하지 않은 경우 해당 과목도 표시해야 한다. 학점 외 요건(세부전공필수·졸업논문·TOPCIT)도 충족 여부와 부족한 부분을 표시한다(예: 세부전공필수 지정 과목 중 몇 과목을 더 들어야 하는지).

### 1.5 수강계획 시뮬레이션 (Phase 2)

사용자가 앞으로 수강할 과목을 추가하여 졸업요건 충족 여부를 미리 확인할 수 있어야 한다.

예시:

```text
현재 상태
전공필수 21 / 27

다음 학기
A 과목 3학점
B 과목 3학점

시뮬레이션 결과
전공필수 27 / 27
→ 충족
```

### 1.6 수강과목 추천 (Phase 3)

시스템은 사용자의 부족한 졸업요건을 바탕으로 수강이 필요한 과목을 추천할 수 있어야 한다.

추천 시 다음 조건을 고려할 수 있다.

- 부족한 졸업요건
- 이미 이수한 과목
- 선수과목
- 해당 학기 개설 여부
- 최대 수강학점

## 2. 비기능 요구사항

### 2.1 정확성

졸업요건 판정은 광운대학교 공식 학사자료를 기준으로 이루어져야 한다.

AI 활용 원칙([project-plan.md](./project-plan.md) 7번 참고)에 따라, AI가 추출·정리한 데이터는 반드시 원본과 사람이 대조 검증한 뒤에만 판정 로직에 반영한다.

> TODO([#7](https://github.com/wonmnms/GradGak/issues/7)): 검증 절차를 구체화할 것 — 누가(팀원 역할), 어떤 방식으로(예: 원본 대조 체크리스트, 표본 검수 등), 어느 시점에(데이터 반영 전/PR 리뷰 시) 검증할지 다음 회의 이후 정한다.

### 2.2 유지보수성

학사 규정 및 교육과정 데이터는 판정 로직과 분리하여 관리한다([project-plan.md](./project-plan.md) 7번 원칙 적용).

### 2.3 확장성

향후 다른 학과 및 입학년도의 졸업요건을 추가할 수 있어야 한다.

### 2.4 사용성

사용자는 복잡한 학사 규정을 직접 확인하지 않아도 자신의 졸업 진행 상황을 쉽게 파악할 수 있어야 한다.

## 4. 데이터 요구사항

시스템은 광운대학교의 공식 학사자료를 기반으로 졸업요건 및 교육과정 데이터를 관리해야 한다.

### 졸업요건 데이터

- 입학년도
- 학과
- 졸업학점
- 교양 관련 요건
- 전공 관련 요건
- 필수 이수과목
- 기타 졸업요건

### 과목 데이터

- 학수번호
- 과목명
- 학점
- 이수구분
- 개설 학기
- 선수과목
- 개설 학과

학사 규정 및 교육과정은 입학년도에 따라 달라질 수 있으므로 연도별로 구분하여 관리한다.
