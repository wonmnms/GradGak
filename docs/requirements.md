# Requirements

## 1. 기능 요구사항

### 1.1 사용자 정보 입력

사용자는 다음 정보를 입력할 수 있어야 한다.

- 입학년도
- 학과
- 현재 학기
- 복수전공 및 부전공 여부

### 1.2 이수과목 관리

사용자는 자신이 이수한 과목을 등록하고 관리할 수 있어야 한다.

- 과목 검색
- 과목 추가
- 과목 삭제
- 이수 학기 입력
- 이수 학점 확인

### 1.3 졸업요건 분석

시스템은 사용자의 입학년도, 학과 및 이수과목을 바탕으로 졸업요건을 분석해야 한다.

분석 대상은 다음과 같다.

- 총 졸업학점
- 교양필수
- 교양선택
- 전공필수
- 전공선택
- 졸업 필수과목
- 복수전공 및 부전공 요건

각 항목에 대해 다음 정보를 제공해야 한다.

- 요구 조건
- 현재 이수량
- 부족한 양
- 충족 여부

### 1.4 부족 요건 안내

졸업요건을 충족하지 못한 경우 부족한 요건을 사용자에게 명확하게 표시해야 한다.

예시:

```text
전공필수
27학점 필요 / 21학점 이수
→ 6학점 부족
```

필수 과목을 이수하지 않은 경우 해당 과목도 표시해야 한다.

### 1.5 수강계획 시뮬레이션

사용자가 앞으로 수강할 과목을 추가하여 졸업요건 충족 여부를 미리 확인할 수 있어야 한다.

예시:

```text
현재 상태
전공필수 21 / 27

다음 학기
A 과목 3학점
B 과목 3학점

시뮬레이션 결과
전공필수 27 / 27
→ 충족
```

### 1.6 수강과목 추천

시스템은 사용자의 부족한 졸업요건을 바탕으로 수강이 필요한 과목을 추천할 수 있어야 한다.

추천 시 다음 조건을 고려할 수 있다.

- 부족한 졸업요건
- 이미 이수한 과목
- 선수과목
- 해당 학기 개설 여부
- 최대 수강학점

---

## 2. 비기능 요구사항

### 2.1 정확성

졸업요건 판정은 광운대학교 공식 학사자료를 기준으로 이루어져야 한다.

### 2.2 유지보수성

학사 규정 및 교육과정 데이터는 판정 로직과 분리하여 관리한다.

### 2.3 확장성

향후 다른 학과 및 입학년도의 졸업요건을 추가할 수 있어야 한다.

### 2.4 사용성

사용자는 복잡한 학사 규정을 직접 확인하지 않아도 자신의 졸업 진행 상황을 쉽게 파악할 수 있어야 한다.

---

## 3. 개발 단계

### Phase 1 — MVP

다음 기능을 우선 구현한다.

- 입학년도 선택
- 학과 선택
- 이수과목 입력
- 졸업학점 계산
- 졸업요건 판정
- 부족한 졸업요건 표시
- 필수 미이수 과목 표시

### Phase 2 — 수강계획 시뮬레이션

- 수강 예정 과목 입력
- 수강 후 졸업요건 재계산
- 학기별 수강계획 관리
- 선수과목 및 개설학기 반영

### Phase 3 — 수강계획 추천 및 최적화

- 부족한 졸업요건을 충족하기 위한 과목 추천
- 수강 가능 학점 고려
- 졸업 예정 학기 예측
- 최적 수강계획 탐색

### Phase 4 — 서비스 확장

- 복수전공 및 부전공
- 다양한 학과
- 다양한 입학년도
- 자연어 기반 결과 설명

---

## 4. 데이터 요구사항

시스템은 광운대학교의 공식 학사자료를 기반으로 졸업요건 및 교육과정 데이터를 관리해야 한다.

### 졸업요건 데이터

- 입학년도
- 학과
- 졸업학점
- 교양 관련 요건
- 전공 관련 요건
- 필수 이수과목
- 기타 졸업요건

### 과목 데이터

- 학수번호
- 과목명
- 학점
- 이수구분
- 개설 학기
- 선수과목
- 개설 학과

학사 규정 및 교육과정은 입학년도에 따라 달라질 수 있으므로 연도별로 구분하여 관리한다.

---

## 5. 범위 제한

프로젝트의 개발 기간과 인력을 고려하여 초기 버전에서는 제한된 학과 및 입학년도를 대상으로 개발한다.

구체적인 지원 범위는 데이터 조사 이후 확정한다.

## 6. 향후 고려사항

- 학사 규정 변경에 따른 데이터 갱신
- 졸업요건 판정 결과의 정확성 검증
- 여러 학과 및 입학년도 지원
- 복수전공 및 부전공 규정의 복잡한 조건 처리
- 수강계획 최적화
