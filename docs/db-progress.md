# 중간보고용 DB 개발 현황

기준일은 2026-10-31이다. DB 스키마와 공식 초기 규칙 데이터의 저장·조회 기반을
구현하고 실제 PostgreSQL에서 검증했다. 전체 졸업판정 데이터 구축 및 API 통합은 완료 전이다.

## 구현 결과

| 항목 | 구현 및 확인 내용 |
| --- | --- |
| 데이터 구조 | SQLAlchemy 도메인 모델 11개, 관계도 작성 |
| DB 변경 관리 | Alembic 마이그레이션 7개, 실제 PostgreSQL 적용 |
| 초기 공식 학점 | 2024학번 두 세부전공·두 프로그램의 총학점과 영역별 최소 학점 |
| 과목 그룹 | 인공지능전공 5과목 중 3과목, 공학 필수 이수 5개와 캡스톤 택1 |
| 공통 비학점 | 졸업논문·작품 제출 및 '가' 판정, TOPCIT 응시의 규칙 정의 |
| 출처 관리 | 공식 URL·조회일·원본 대조 범위·확인 기록 |
| 백엔드 전달 | 입학년도·프로그램·세부전공별 규칙 조회 함수와 CLI |
| 자동 검증 | pytest 43개 통과, 코드 규칙·형식 검사 및 DB/모델 비교 |
| 재현 | 빈 임시 스키마에 전체 마이그레이션·시드 반복 입력·네 범위 조회 성공 |

## 공식 초기 데이터 건수

아래는 가상 데이터 없이 빈 스키마에서 재현한 결과다.

| 데이터 | 건수 |
| --- | ---: |
| 졸업요건 범위 | 4 |
| 영역별 학점 조건 | 20 |
| 교과목 | 12 |
| 과목 그룹 | 14 |
| 과목 그룹·교과목 연결 | 24 |
| 공통 비학점 규칙 | 4 |
| 자료 출처 | 2 |
| 졸업요건·자료 검증 연결 | 6 |

과목명 별칭·대체 인정·영역별 인정 과목 연결은 테이블과 관련 무결성 검증을 구현했으나,
공식 실제 데이터는 아직 입력하지 않았다. 개발 DB에는 별도의 2099년 TEST 데이터가 있으므로
전체 테이블 건수는 위 공식 데이터 건수와 다를 수 있다.

## 검증한 동작

- 중복 과목코드·별칭·규칙 및 존재하지 않는 졸업요건 참조를 거부한다.
- 대체 인정은 적용 졸업요건 범위와 방향을 구분한다.
- 과목 그룹의 최소 이수 개수는 양수여야 한다.
- 자료 검증 완료에는 확인자·확인일이 필요하다.
- 초기 데이터는 재실행 시 재사용하고 기존 값과 충돌하면 중단한다.
- 공학 선택 시 공학·일반 학점 규칙을 함께 조회하고 공통요건은 한 번만 반환한다.
- 없는 학번·잘못된 프로그램·필수 규칙 누락을 다른 규칙으로 대체하지 않는다.
- 수학·과학은 기초교양, 설계는 공학주제의 하위 조건으로 조회된다.
- 미확인 학수번호·이수구분·과목 학점은 NULL로 유지한다.

테스트 통과는 위 구현 동작의 검증이며 학사 규정 전체의 정확성을 보증하는 지표는 아니다.
기존 테스트 도구에서 발생하는 httpx 사용 방식의 지원 중단 예정 경고 1건은 별도 남아 있다.

## 남은 작업과 협업 경계

- 영역별 인정 과목 목록, 프로그램별 학점 인정 차이, 교양의 세부 영역·과목 수·면제 조건.
- 미확인 학수번호와 공학 필수과목별 학점, 과목명 변경·대체 인정의 공식 실제 데이터.
- 위 자료를 원본과 대조하고 구조화·입력하는 후속 데이터 작업.
- 백엔드 담당의 이수내역 판정 계산과 API 연결, 전체 사용자 흐름 통합.
- GitHub CI 실제 실행 결과, PR 및 팀원 리뷰. 로컬 검사와 구분한다.

DB 조회 결과는 `data_complete: false`를 반환한다. 이를 최종 졸업판정 가능 상태로
표시하거나 전체 서비스 개발 완료율로 사용하지 않는다.

## 시연

```powershell
docker compose exec backend python -m app.show_rules --program engineering --sub-major ai
docker compose exec backend pytest -v
docker compose run --rm --no-deps -v "${PWD}/backend:/app" backend alembic check
```

새 DB 재현 검증은 임시 스키마를 생성할 권한이 있는 개발용 DB에서 실행한다.
스크립트가 생성한 임시 스키마만 정리하며 기존 스키마는 변경하지 않는다.

```powershell
docker compose run --rm --no-deps -v "${PWD}/backend:/app" backend python -m scripts.verify_fresh_db
```

구조와 조회 계약은 [DB 스키마](db-schema.md), 원본 대조 범위는
[데이터 검증 기록](data-verification.md), 실행 절차는 [DB 개발 가이드](db-setup.md)를 참고한다.
