# 결과 화면 mock 구현 (#25)

## 구성

- ResultsPage.tsx: 프로그램 비교, 학점 표, 특수요건, 미이수 필수과목, 수정 화면 복귀
- ResultsPage.module.css: 반응형 스타일. 공통 디자인 변수를 재사용
- result.types.ts: 화면 전용 타입. API 명세가 아님
- results.mock.ts: 전부 가상 데이터인 다섯 시나리오(미충족 / 충족 / 확인 필요 / 일반 충족·공학 미충족 / 학점 충족·논문 미충족)
- ../../context/program.ts: 프로그램 문자열 인식. 빈 값·알 수 없는 값은 null
- ../../../tests/results.test.mjs: 프로그램 인식·가상 데이터 일관성 회귀 테스트 7개

공학 선택 시 두 프로그램을 표시하고, 일반 선택 시 일반만 표시한다. 업로드·검수 화면의 공통 프로그램 입력은 선택형이며 기존 Context 문자열 값인 '공학'/'일반'을 유지한다. 기존 값 '공학 프로그램'/'일반 프로그램' 및 engineering/general도 인식한다. 빈 값·알 수 없는 값은 공학으로 추정하지 않으며, 결과 카드 대신 선택 안내를 표시한다. 예시 프로그램을 선택해도 원래 검수 입력은 수정하지 않는다.

학점 충족·논문 미충족 예시에서는 학점 이수율이 100%여도 프로그램 전체는 미충족이다. 이는 가상 데이터 표시 테스트이며 실제 학교 판정 규칙의 구현이 아니다.

학점/상태/과목은 실제 입력으로 계산하지 않는다. 진행 막대만 전달된 총학점 수치의 비율로 표시한다. 이 비율은 졸업 가능 여부의 백분율이 아니다. 모든 수치는 실제 학교 규정으로 사용하면 안 된다.

## 확인한 동작

- 개발 서버에서 Vite 변환 및 렌더링 정상
- 공학/일반 표시 전환
- 충족 상태의 부족학점 0, 미이수 과목 없음
- 확인 필요 상태의 미확정 요건 안내
- 검수 화면 복귀, 원래 프로그램 입력 보존, 결과 초기 선택 반영
- 본문 380px에서 가로 넘침 없음
- 설치된 TypeScript 5.9.3으로 현재 src 16개 파일과 타입 라이브러리를 가상 파일 호스트에 로드하여 strict 타입 검사: 오류 0
- 설치된 Prettier 3.9.10으로 변경 파일 포맷 적용 및 검사

## 검사 기록 (2026-10-27)

- 보완 후 npm run test:results: Node 테스트 러너에서 7개 통과, 실패 0. 사용자가 공유한 터미널 출력으로 확인.
- 보완 후 npm run build: tsc -b 및 Vite 프로덕션 빌드 성공. 61개 모듈 변환, 785ms. 사용자가 공유한 터미널 출력으로 확인.
- npm run lint: 사용자가 실행했다고 알렸으나 이번 최종 종료 코드가 포함된 출력은 수집하지 않음. PR 준비 스크립트에서 재검사.
- 변경 파일 Prettier 검사 통과. 전체 npm run format:check는 PR 준비 스크립트에서 재검사.
- 프로그램 미선택 안내, 일반 입력 전달, 두 비교 예시, 예시 선택 후 검수 입력 보존을 브라우저에서 확인.

현재 코드는 실제 졸업 판정이 아닌 mock UI다. GitHub 푸시와 PR 게시는 별도 승인 후 진행한다.

## 공통 코드 변경 범위

공통 DraftFields의 프로그램 필드만 선택형으로 변경했고 공유 인식 함수 context/program.ts를 추가했다. 다른 세 입력 필드와 API 미확정 Context 구조는 유지했다. 업로드·검수 화면 담당자에게 이 변경을 함께 공유해야 한다.
